# Mansion Security 自动应答 · Home Assistant 自定义集成

版本 0.4.0，验证目标 Home Assistant Core **2026.9.4 / Python 3.14**。支持在 HA 内输入用户名、密码和二维码字符串登录，使用 App 已有的大厅 `ロビーインターホン` 预设。

全部持久预设直接显示并可选择，无需开启额外选项。HA 每 60 秒读取真实状态，不按本地两小时计时主动关闭。HACS 更新后重启 HA 生效，已有账号配置继续使用。

手机关机时，独立 HTTPS 客户端和隔离的真实 HA Core 实例均已完成“关闭 → 稍后再来 → 关闭”的写入和回读。用户名密码登录、手动二维码配对及必要的初始化也已在真实服务中验证。**家庭 HA OS 的完整验收，以及楼下实际呼叫和语音应答尚待完成。** 验证后已恢复关闭。

## 通过 HACS 安装

仓库：[xtymmms1021/mansion-security-ha](https://github.com/xtymmms1021/mansion-security-ha)。

1. 打开 HA 的 HACS，点击右上角“⋮ → 自定义存储库 / Custom repositories”。
2. 仓库地址填 `https://github.com/xtymmms1021/mansion-security-ha`，类别选“集成 / Integration”，点击添加。
3. 搜索并打开 **Mansion Security**，下载最新版本，然后重启 Home Assistant。
4. 在“设置 → 设备与服务 → 添加集成”中搜索 Mansion Security，选择“用户名和密码登录”，按下节完成登记。已有可用配置升级时无需重新登录。

HACS 负责安装和更新集成文件，账号认证仍在 Mansion Security 集成中完成。从手动安装切换到 HACS 时，实体和现有配置可以继续使用，无需先删除集成条目。

仓库只包含程序、说明、示例和脱敏验证记录，真实账号凭据不在 GitHub。使用已由物业或 SECOM 分配的账号；本集成不创建新的服务账号。

参考：[HACS 自定义仓库说明](https://www.hacs.dev/docs/faq/custom_repositories/)。

## 用户名、密码和二维码字符串登录

1. 在手机 App 中正常退出。此服务只允许单账号登录；HA 与手机 App 不能分别新建并行会话。
2. 添加 Mansion Security 集成，选择“用户名和密码登录”，输入用户 ID 和当前有效密码。
3. 在下一页手动粘贴门铃贴纸二维码解码后的完整字符串，填写昵称并阅读注意事项。不需要相机、图片上传、ADB 或 Windows 工具。
4. 集成会先尝试直接读取。若服务端已经允许访问，就完成登记，**不会修改密码**。
5. 若配对后服务端仍返回 `invalidUser`，才显示密码初始化表单。你提交后会实际修改账号密码；须为 8–32 位半角字母、数字或符号，不含空格，且与当前密码不同。
6. 配对和读取完成后，创建“自动应答模式”实体。目标住户由账号和二维码确定，不需要再输入房号。

**关于跳过改密：**2026-10-17 对此次账号做了两次真实测试：登录后直接读取、配对登记后读取均返回 `invalidUser`；使用相同旧密码和新密码初始化返回 `changeFailed`，更换昵称后结果仍相同。因此，在这次服务端要求的初始化中，无法保留原密码。集成不会无条件要求换密，也不会在日常同步或 HA 重启时换密。

密码只用于当前配置流程，不保存在 HA 配置、会话码或 GitHub 中。HA 保存会话密钥和配对资料，后续独立运行。设备登记使用每个 HA 配置随机生成的设置专用标识，已验证服务端接受；本集成不订阅手机呼叫推送。

若改密后的登记中断，可在“继续完成登记”页重试配对和读取，不会重复改密。未完成的会话保存在 HA 的私有 `.storage/mansion_security.pending_registration` 中以便恢复，其中不含密码；重新发起登录时可恢复同一账号已完成初始化的会话。

## 手动安装及已有会话导入（可选）

1. 解压安装包。将包内整个 `custom_components/mansion_security` 文件夹复制到 HA 的 `/config/custom_components/mansion_security`。可使用自己已安装的文件编辑或文件共享工具。如果 `custom_components` 不存在，先创建它。
2. 检查路径应为 `/config/custom_components/mansion_security/manifest.json`，避免重复嵌套目录。无需复制 `tools`、`tests` 到 HA，也无需在 HA OS 中安装 Python 或 ADB。
3. 重启 Home Assistant。
4. 如果已有完成登记的会话，可在本次 Windows 电脑上双击 `tools/start_setup.cmd`，点击“查看并复制 HA 私密会话码”，复制 `MSHA1.` 开头的完整内容。通常可以按上节直接在 HA 登录，无需使用此工具。
5. 在 HA 中打开“设置 → 设备与服务 → 添加集成”，搜索 **Mansion Security**，选择“导入已有会话（高级）”，粘贴会话码。此方式不会重新登录或修改密码。
6. 账号只绑定一个住户房间，接口也只返回该房间，因此目标自动确定。无需输入房号或另选设备。
7. 在实体详情中查看并记下实际实体 ID，供自动化使用。把实体加入仪表盘即可选择预设。首次状态应显示“关闭”。

如果添加集成列表中没有出现它，请检查复制路径和 HA 日志，并确认已经重启。HA 对自定义集成显示通用提示属于正常行为。

## 会话和账号

此服务限制单账号并行登录。将账号用于 HA 时，手机 App 应保持退出。登记或导入完成后，HA 启动、重启和普通同步都不会再次调用登录，也不会重新修改密码。

会话码含访问密钥、门铃配对资料和设备登记标识，属于私密凭据，Base64 编码不是加密。使用会话导入时，请把完整会话码保存到自己的密码管理器；安装包不含任何真实账号凭据。HA 在自己的配置存储中保存会话，备份也应按凭据保管。

Windows 工具仅监听 `127.0.0.1`，会话资料使用当前 Windows 用户的 DPAPI 加密保存在 `%LOCALAPPDATA%\MansionSecurityHA`。密码不会写入文件。该目录不在安装包内。当前电脑已经准备好资料；更换电脑时可在工具的输入页粘贴先前保存的会话码恢复资料。

复制完成后可关闭工具。HA 正常运行不需要电脑、ADB、手机或本机页面常驻。不要在正常使用期间运行“重新完成账号登记”。

## 模式与行为

| HA 选项 | 模式 ID | 入口门动作 |
| --- | --- | --- |
| 关闭（动作参数为 `off`） | `0` | 关闭自动应答 |
| ただいま手が離せません。後ほどお越し下さい | `24` | 不自动解锁，稍后再来 |
| 荷物はフロアの宅配ボックスへ入れてください（自动开门） | `33` | 自动解锁 |
| どうぞお入りください（自动开门） | `23` | 自动解锁 |

全部持久预设默认显示并可直接选择，包含两种自动开门预设；名称保留“（自动开门）”提示。0.4.0 已移除“允许自动开门预设”开关，旧配置中该开关的值不再影响显示或设置。每次写入前仍会重新读取服务端列表，确认模式存在且支持提前设置，并在写入后回读确认。自动开门预设的测试使用模拟服务，尚未做实际开门效果验收。

启用状态与所选预设由服务端同一个设置接口控制；没有独立启用开关。因此用一个 `select` 实体统一控制，关闭也是一个选项。

App 文案说明预设有效期为 **2 小时**。HA 不会为了维持预设而定时重复设置，实际到期行为仍待长时间现场验证。重复执行设置可能重新计算有效时间，自动化应按实际需要触发。

HA 启动时读取真实状态，默认每 60 秒同步。每次写入后立即 GET 回读，只有确认匹配才更新显示。超时、协议异常或写入无法确认时显示“不可用”，不会乐观宣称设置成功；普通网络故障后下一次成功读取可恢复。

## 自动化示例

将 `examples/actions.yaml` 中的 `select.your_mansion_security_mode` 换成实际实体 ID，然后在“开发者工具 → 动作”的 YAML 编辑器中运行其中一个动作：

```yaml
action: select.select_option
target:
  entity_id: select.your_mansion_security_mode
data:
  option: "ただいま手が離せません。後ほどお越し下さい"
```

关闭使用 `option: "off"`，即使前端显示“关闭”，动作仍使用 `off`。预设名称以当前实体的 `options` 属性为准。完整的“离家时设置”示例在 `examples/automations.yaml`，使用前还须替换实际 `person` 实体。

## 配对续期与重新认证

此次服务端返回的配对期限为 2027/04/17，期限字段为 6 个月。HA 在期限前 7 天开始使用已保存的配对资料续期，保存新的到期日。手机关机时的同一接口调用已验证成功；实际跨越六个月的长期运行尚未验证。

如果服务端拒绝会话，实体会不可用，HA 会显示重新认证入口。可以直接选择“用户名和密码登录”，使用同一账号按上节重新完成登记。已有配对资料会自动填入，可手动修改；服务端能直接读取时不要求改密。

也可以用已有的新会话更新认证：

1. 暂时停用 HA 中的 Mansion Security 集成，确认手机 App 已正常退出。
2. 如果本机已有完成登记的会话，在 Windows 双击 `tools/start_setup.cmd` 直接复制会话码；否则优先在 HA 内登录。Windows 工具仍保留显式重新登记功能，其中的表单会实际修改密码，不能用于普通查看会话码。
3. 在 HA 的重新认证菜单中选择“导入新的会话”，提交新会话码并启用集成。必须为同一账号。

若出现 `alreadyLoggedIn`，服务端仍认为账号被占用，应先处理原 App 的正常退出，不要连续尝试初始化。若密码已经改好、后续登记失败，工具只提供“重试剩余登记”，不会再次改密。

若改密请求超时、结果无法确认，工具会阻止重放。先使用官方 App 确认当前有效密码并正常退出，备份 `%LOCALAPPDATA%\MansionSecurityHA\registration-status.json` 后移走该状态文件，再打开工具处理。保留 `session.dpapi`，不要猜测密码状态反复初始化。

账号迁回手机可能需要完整扫描配对和改密流程，也可能令 HA 旧会话失效；目前没有证据支持两端同时在线登录。

## 现场验收（待完成）

保持安卓手机完全关机，在家中 HA OS 安装并导入后：

1. 确认实体为关闭，然后选择“ただいま手が離せません。後ほどお越し下さい”。等待实体回读确认。
2. 在楼下大厅呼叫本住户，确认听到“稍后再来”对应的应答，且入口门没有解锁。
3. 在 HA 选择关闭，再次呼叫并确认恢复通常行为。
4. 重启 HA，确认能恢复真实状态；不需要重新登录。

此次接口没有暴露服务端或门铃固件的内部执行位置，因此现在能证明的是云端设置在手机离线时可修改和保存。实际离线应答是否生效，需要上述呼叫验收确认。

## 验证与源码

85 项离线测试在真实 HA Core 2026.9.4 / Python 3.14.4 环境通过；覆盖新配置及旧开关关闭/开启时全部预设的显示和选择，以及两种自动开门预设的模拟写入和回读。另有 2 项早期真实云端 HA 测试通过，分别覆盖已有会话控制及用户名密码完整登记后控制。真实服务测试在隔离实例中执行，不能代替家庭 HA OS 的现场验收。测试范围和未测项目见 `docs/协议验证记录.txt` 与 `docs/verification.json`。

开发测试环境：Linux、Python 3.14，安装 `requirements-test.txt` 后在包根目录执行 `python -m pytest -q`。默认测试禁止外网访问，网络测试只使用本机模拟服务，不需要真实凭据。协议客户端位于 `api.py`，与 HA 配置、协调器、实体分离。

卸载：先在 HA 中选择关闭并确认，随后删除集成条目，再移除 `/config/custom_components/mansion_security` 并重启。删除集成不会自动注销云端账号或恢复手机登录。
